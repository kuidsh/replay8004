Independent checks for AI agents on Celo

replay8004 is an open-source validator for the ERC-8004 Validation Registry. An agent names it with a claim anyone can check on Celo, such as "this payment settled". It re-executes the claim against chain state and answers on-chain with a 0–100 score and evidence anyone can recompute.

From a claim to an on-chain answer, usually within a minute

Nothing runs from the job: replay8004 only reads Celo state. Anything it can't check yet stays pending and is never scored 0, and no request is answered twice.

The agent states a claim

A small job file: "tx T paid ≥ X of token K to B", an x402 receipt, a balance or a contract read. Its keccak256 is the requestHash.

Its owner asks on-chain

validationRequest(replay8004, agentId, requestURI, requestHash) on the ERC-8004 Validation Registry.

replay8004 re-checks it

Downloads the job, checks the hash, agent and chain, waits for confirmations and re-runs the claim against Celo.

It answers with evidence

Writes the evidence bundle first, then validationResponse with the score, a tag and the bundle's hash.

Four kinds of claims, all re-executed against Celo

The agent saysHow replay8004 checks itTag
"This x402 receipt is real"The payment requirements and the settlement match the network; the tx succeeded and is confirmed; the asset moved from payer to payTo and covers the amount; optional EIP-3009 nonce and facilitator checks. A receipt that reports more than moved scores 0.replay:x402_settlement
"Tx T paid at least X of token K to B"Reads the receipt: status, the Transfer log, confirmations. The score scales with the amount actually paid.replay:erc20_transfer
"Holder H had balance X at block N"balanceOf(H) through eth_call at block N, with an optional tolerance.replay:erc20_balance
"Calling f(args) on C at block N returned X"The same eth_call at block N, ABI-decoded and compared.replay:contract_read

Free for agents building on Celo

Up to 20 answers a day and 5 per agent, so nobody can drain the validator. Mainnet validator 0xD2d6c6DEaaDF2A5868e8e0C17d674D49531C5952.

Ask for a validation

Builds the job and the validationRequest calldata. Your agent's owner sends it from their own wallet; nothing is signed here.

git clone https://github.com/kuidsh/replay8004
cd replay8004 && pip install -e .
replay8004 job x402-settlement --agent-id <id> \
  --validator 0xD2d6c6DEaaDF2A5868e8e0C17d674D49531C5952 \
  --requirements accepted.json --settlement "$PAYMENT_RESPONSE"

Also as a TypeScript client (clients/ts), a read-only MCP server and an Agent Skill.

Don't trust the validator either

Every answer links to a JSON evidence bundle in a write-once (Object Lock) bucket. Download it, hash it and compare with the responseHash on-chain, then follow prev back to the first answer.

replay8004 verify-evidence <folder of bundles>
