replay8004

An open-source re-execution validator for ERC-8004's Validation Registry on Celo, which has recorded no answers since March 2026. An AI agent claims something an outsider can check on Celo (for example, that it paid for an API call). replay8004 re-checks the claim against chain state and answers on-chain with a score from 0 to 100, plus evidence anyone can recompute.

Each answer is validationResponse(requestHash, score, responseURI, keccak256(bundle), tag). Bundles chain by hash, #1 → #4, so a skipped or edited answer shows up: verify-evidence reports "4 bundles, chain intact".

How a validation flows

agent owner ── validationRequest(validator, agentId, requestURI, keccak256(job)) ──▶ ValidationRegistry (Celo)
                                                                                       │ ValidationRequest event
replay8004 worker (every minute) ◀── eth_getLogs(topic1 = validator) ──────────────────┘
  1  fetch requestURI (https / ipfs / inline data:) and check keccak256 == requestHash
  2  check that the job's agentId and chainId match the on-chain request
  3  re-run the claim against Celo; wait for confirmations, never answer early
  4  write the evidence bundle (S3 Object Lock), hash-chained to the previous one
  5  validationResponse(requestHash, score, responseURI, responseHash, tag)

Why this gap exists

  • Identity and reputation are in use on Celo, validation isn't. The registry at 0x8004Cc8439f36fd5F9F049D9fF86523Df6dAAB58 has had 39 transactions. Its 21 requests were all for one agent (#1870) on 2026-03-19, and 17 were answered. Nothing since (Blockscout, checked 2026-11-21). Self's own validation registry on Celo has 2 transactions, both role grants.
  • Reputation alone is weak. A 2026 study of 173k ERC-8004 agents on Ethereum, BSC and Base found that 98.7–100% of feedback has no payment proof or task link, and that sybil reviewers make up 59–91% of reviewers. Its authors ask for feedback tied to a verifiable interaction such as a settled x402 payment, which is exactly the erc20_transfer check.
  • The registry spec is still moving (the TEE section is under revision). replay8004 only uses the stable calls: validationRequest, validationResponse and getSummary.
